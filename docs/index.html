Engram is agent memory on HydraDB. It recalls the version of a fact that is true right now, proves where it came from, and says it does not know when the answer is not in the history. Vector search cannot do any of that.

How it works

A temporal provenance graph, on HydraDB.

Every conversation history becomes a graph that HydraDB traverses. Answers are graph walks, not similarity lookups.

1

Ingest

Sessions hold messages, messages state facts, facts are about entities. Any fact that updates an earlier one gets a SUPERSEDES edge.

2

Traverse

A typed multi hop MATCH over STATES, ABOUT, and SUPERSEDES, then a filter to the fact that is current.

3

Answer with a receipt

Answer only from that evidence, and attach the source message plus the value it replaced. If nothing supports it, abstain.

Benchmark

Even on accuracy, ahead on trust.

LongMemEval-S, the same model for both systems, judged by an LLM. Accuracy is close. What only Engram gives you is a receipt for every fact and a refusal to guess.

CategoryEngram (graph)Vector RAG
knowledge-update71%67%
multi-session30%20%
abstention100%100%
temporal-reasoning20%60%

On this small sample the two are close. Engram's edge is the receipt and the abstention, which a vector retriever cannot produce. Date arithmetic is its weak spot.
